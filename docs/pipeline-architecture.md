# 1,000 브랜드 헤리티지 자동 발행 파이프라인 설계 (2026-08-03)

목표 4개: ① 1,000개 럭셔리 브랜드 학습 ② SNS(@1club.kr) 자동 발행 ③ 브랜드-정보-이미지 정합성 + 출처 정확성 + 고급 감도 ④ 성과분석 일원화.

## 랜딩페이지 신규 제작 여부 판단

**결론: 새로 만들지 않는다. 현재 에디터를 유지하되 데이터를 분리한다.**
- 유지 가치: 카드 렌더러·타이포 시스템·매거진 커버 엔진·누끼 도구·중복 가드·CONTENT_POLICY 게이트는 이미 검증됨. 새로 만들면 이걸 다시 만드는 비용만 발생.
- 문제는 UI가 아니라 데이터 구조: index.html 26MB 모놀리스(base64 내장)가 확장을 막는 유일한 병목.
- 파이프라인 상태 보드(브랜드별 티어/검수 상태/발행 큐)는 에디터에 탭으로 추가.

## Phase 1 — 데이터 분리 (모놀리스 해체)

- `data/brands.json` (INFO+FACTS), `data/manifest/<brand>.json` (이미지: slot·originalId·sourceUrl·license·credit), `assets/<brand>/` 파일.
- BRAND_MEDIA(만료 인스타 CDN 82개) 삭제. CAT_IMGS는 Tier 3 폴백 전용으로 강등 + `SOURCE REVIEW` 표기 강제.
- **전역 중복 레지스트리**: originalId 1개 = 브랜드 1개 (세트 내부는 기존 used-set 가드 유지).

## Phase 2 — 브랜드 학습 (864 → 1,000)

- **카피**: 브랜드당 8필드(heritage/founderStory/product/behind/quote 등) LLM 배치 생성 + 팩트 게이트(founded·founder·place·productName은 Wikipedia/Wikidata 대조, 인용문은 출처 실존 확인. 출처 없는 인용문 생성 금지).
- **이미지**: iconic-imagery.js 스코어링을 카테고리별 배치로 확장 (Wikimedia Commons + 브랜드 공식 프레스룸). 합격 기준: 브랜드명 증거 필수 / 8장 originalId 전부 고유 / 라이선스 기록 / 미달 시 SOURCE REVIEW.
- **티어제**: Tier 1(발행 가능, 검수 완료) / Tier 2(자동 큐레이션, 검수 대기) / Tier 3(폴백). 발행 큐 진입 시점에 승급.
- 배치 단위: 카테고리별 20~30개 브랜드, 배치마다 자동 검증 스크립트 통과 필수 + 10% 스팟체크.

## Phase 3 — 자동 발행

- 헤드리스 렌더(현 에디터 renderToCanvas 재사용) → 2160×2700 PNG 8장 + 캡션(해시태그 `#BrandHeritage` + 회차 태그).
- IG Graph API 캐러셀 발행 (기존 instagram_sync 토큰 인프라 재사용).
- 발행 캘린더: 에디터의 발행 캘린더 탭과 연동, 주 N회 자동.
- **휴먼 게이트**: 초기 3개월은 발행 전 슬랙(#2_contents) 시안 컨펌 후 발행. 무사고 안정화 후 완전 자동 전환.

## Phase 4 — 성과분석

- 콘텐츠DB(매일 08:00 동기화)에 이미 인입되므로 신규 수집 불필요 — 발행 시 미디어ID를 시리즈 레지스트리에 기록해 태깅만 추가.
- 브랜드/카테고리/카드 아키타입별 조회수·저장·공유 리포트 → 어떤 브랜드·카테고리가 반응 좋은지 → **다음 발행 우선순위에 피드백** (반응 좋은 카테고리의 Tier 2 브랜드를 먼저 승급).
- 주간 리포트는 기존 채널별 주간 콘텐츠 리포트(월 10:05)에 섹션 추가.
