## 중복·오배정의 근본 원인 (실측)

1. **브랜드 간 공용 풀 공유**: 카테고리당 이미지 풀이 슬롯별 3~12장뿐인데 그 풀을 카테고리 전체 브랜드가 공유한다.
   - fashion: 170개 브랜드가 14장(product 6 / space 4 / craft 4) 공유 → **같은 사진이 최대 수십 개 브랜드 세트에 등장**
   - furniture 69개/14장, hotel 58개/14장, fragrance 57개/14장 등 전 카테고리 동일 구조
   - "그 브랜드 이미지가 아닌 이미지"가 들어오는 것도 같은 원인: 공용 풀 이미지는 브랜드 무관 업종 스톡이다.
2. **세트 내부 중복**은 `imgAssign()`의 used-set 가드로 이미 차단됨 (정상 동작 확인). 문제는 세트 간(브랜드 간) 중복.
3. **만료 CDN 의존**: BRAND_MEDIA의 인스타그램 서명 URL 82개 전부 만료 → 43개 브랜드의 "브랜드 실사진" 경로가 사실상 전멸. CONTENT_POLICY가 이미 사용 금지를 명시하므로 데이터 자체를 제거 대상.
4. **단일 파일 모놀리스**: index.html 26MB (CAT_IMGS 17MB + LOGOS 4.8MB + FOUNDER_IMGS 3MB base64 내장). 1,000개 브랜드 자동화 파이프라인으로는 확장 불가 — 데이터/자산/렌더러 분리 필요.

## 티어 제안 (1,000개 브랜드 롤아웃)

- **Tier 1 (발행 대상, 우선 50~100개)**: 전용 검증 이미지 8장 + 검수된 카피. 에르메스 방식(assets/iconic/<brand>/, 슬롯별 1장, 출처·라이선스 manifest).
- **Tier 2 (준비군)**: Wikimedia Commons 자동 큐레이션(iconic-imagery.js 스코어링 재사용) + SOURCE REVIEW 표기.
- **Tier 3 (나머지)**: 카피·이미지 미보유 상태 명시. 발행 큐에 올리는 시점에 Tier 2→1 승급.

## 즉시 조치 항목

1. BRAND_MEDIA(만료 CDN 82개) 데이터 제거 — 렌더 폴백만 남기고 삭제
2. 이미지 전역 중복 레지스트리: originalId 1개 = 브랜드 1개 원칙 (세트 내부는 기존 가드 유지)
3. 데이터 분리: INFO/자산 manifest를 index.html 밖으로 (brands/*.json + assets/<brand>/)
